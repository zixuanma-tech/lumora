第一部分：你要搭建的 Agent 框架清晰表述（可直接贴入项目文档）1. 框架标准命名基于显式状态机的“规划-按需执行-动态重规划”架构（Stateful Plan-Execute-Replan Architecture）。2. 一句话核心机制不依赖单纯的聊天上下文记忆，而是由一个全局结构化状态对象（SessionState）驱动 4 个独立功能算子；前端的所有按钮操作与自然语言反馈统一经过顶层中心路由器（Router）分发，在“保持已参观展品锁定不变”的前提下，实现待参观队列的局部重规划与到站单点讲解按需生成。3. 四层核心结构定义架构层级包含的核心模块 / 文件核心职责边界① 状态与数据底座层(State & Data Layer)• SessionState（会话状态类）• relics.json（展品空间与史料表）• edges.json（审核知识关联表）• 状态机隔离：将展品列表拆分为 visited_relics（只读追加锁，重规划绝不修改）和 pending_queue（可变待办队列）。• 知识底座：提供确定性的展厅位置、专题展标签、两两审核关联边与权威出处。② 顶层路由控制层(Central Router Layer)• dispatch_action()（事件/意图分发器）• 确定性事件直达（0延迟）：点击“开始讲解”、“跳过”、“改时间滑块”、“结束游览”，直接调用对应算子函数，不走大模型判断。• 自然语言意图分类：用户在聊天框自由输入时，调用轻量 LLM 识别意图枚举（REPLAN 重规划 / QA_CURRENT 当前展品追问 / FINISH 结束）。③ 核心执行算子层(Execution Operators)• op_parse_prefs()（需求解析算子）• op_plan_route()（路线规划算子）• op_generate_guide()（单点讲解算子）• op_generate_summary()（探索手记算子）• 算子 1（解析）：把用户初始问卷或中途自然语言反馈转化为结构化的兴趣标签、剩余时长与讲解风格，更新至 SessionState。• 算子 2（规划/重规划）：读取 SessionState，扣除 visited_relics 已看数量后，从候选库筛选补齐至总长 5–8 件展品写入 pending_queue，输出展厅级路径、推荐理由与相邻知识串联点。• 算子 3（单点懒加载讲解）：仅当用户到达某展品时触发，结合上一件已看展品的关联边与权威史料流式生成讲解词，并将该展品移入 visited_relics。• 算子 4（手记生成）：汇总 visited_relics 完整轨迹与沿途知识脉络，输出结构化《探索手记》。④ 端侧交互接口层(API & Mobile UI Layer)• POST /api/event（按钮动作接口）• POST /api/chat（自然语言接口）• 手机 H5 响应式单页• 每次请求处理完毕后，后端统一返回 { reply_content, latest_state }，前端直接根据 latest_state 刷新顶部路线进度条（已参观打勾锁定 vs 待参观队列）。
