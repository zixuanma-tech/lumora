# 寻迹 demo 数据结构说明（data/*.json）

由 `scripts/build_demo_data.py` 从队友整理的国博数据 Excel（`data/国博AI文旅数据收集_官网来源层_20261021.xlsx`）生成。本文档自包含，读完即可写消费这些 JSON 的代码，不需要看 Excel。

## 文件总览与引用关系

| 文件 | 顶层键 | 条数 | 内容 |
| --- | --- | --- | --- |
| `data/relics.json` | `relics` | 60 | 文物主数据（六标签 + 讲解史料 + 知名程度分级） |
| `data/edges.json` | `edges` | 45 | 文物间知识关联（有向） |
| `data/galleries.json` | `galleries` | 4 | 展览/展厅底座 |
| `data/routes.json` | `recommended_routes` | 8 | 推荐主题路线 |
| `data/map.json` | `nodes` / `edges` | 6 / 10 | **虚拟测试空间图**；点到点步行边，与 `data/edges.json` 知识关联边完全分离 |

引用关系（外键均已校验通过）：

```text
relics[].gallery_id            → galleries[].gallery_id
edges[].source_relic_id/target_relic_id → relics[].relic_id
routes[].relic_ids[]           → relics[].relic_id
relics[].materials[].related_relic_ids[] → relics[].relic_id
```

## 通用约定

- 编码 UTF-8（无 BOM）。每个文件顶层除数据键外还有一个 `meta` 对象（`source_file`/`package_version`/`generated`），读取时忽略即可。
- **缺失值的表示**：列表字段一律用空数组 `[]`，**不写 "NA"、不写占位字符串**（原 Excel 的"待专家复核/待视觉核验/待产品侧定义主题"等占位已全部转为空列表，避免污染语义向量）；标量字段缺失时**直接省略键**。因此解析必须用带默认值的取键方式（如 Python `item.get("unit")`），不能假设键一定存在。
- 所有 ID 为稳定字符串主键，来源：`NMC-CQ-104`（文物，CQ=瓷器/YQ=玉器/FS=服饰/TJ=铜镜 四展）、`NMC-EXH-CQ`（展览）、`REL-001`（关联）、`ROUTE-001`（路线）。

## relics.json

### 文物字段（`relics[]`）

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `relic_id` | str | 是 | 主键，如 `NMC-CQ-104` |
| `name` | str | 是 | 官网官方名称，保留原有引号/书名号 |
| `era` | str | 是 | 官方年代原文，如 `北宋（公元960—1127年）`、`明 永乐（公元1403—1424年）` |
| `gallery_id` | str | 是 | 所属展览，指向 galleries |
| `gallery_name` | str | 是 | 展览名称（展示用冗余字段） |
| `hall` | str | 是 | 展厅，四个取值：`北17展厅`/`北18展厅`/`北19展厅`/`南14展厅`（南区/北区可取首字） |
| `status` | str | 是 | 枚举：`核心`(40) / `候选`(20) |
| `demo_use` | str | 是 | 枚举：`优先进入Demo` / `备用/扩展` |
| `importance_level` | int | 是 | **知名程度三档：5=镇馆之宝(7件)、4=核心(33件)、3=候选(20件)**。路线规划中基础分 = 20×level/5；level=5 额外触发"镇馆之宝"待遇（路线途经其展厅时强制纳入并保证驻足） |
| `treasure_note` | str | 否 | 仅 7 件镇馆之宝携带，写标注依据。注意：为网络通行说法+团队判断的**测试用近似口径**，非馆方结论 |
| `tags` | object | 是 | 六标签对象，见下 |
| `materials` | array | 否 | 讲解史料数组。59/60 件有；`NMC-TJ-015` 无官方介绍故整键省略 |
| `unit` | str | 否 | 展览内单元名（30 件缺失） |
| `location_status` | str | 多数有 | 固定为"仅核验到展厅；展柜/展线顺序待实地或馆方确认"——即**没有展柜级坐标** |
| `excavation` | str | 否 | 出土/收藏信息 |
| `source_url`、`page_ref`、`image_url` | str | 否 | 官网页面与图片 |
| `image_note`、`credibility`、`source_note`、`review_note` | str | 多数有 | 版权/可信度/复核备注（可信度统一为 `A官方事实+B保守结构化`） |
| `route_value` | str | 多数有 | 团队写的一句话路线价值（C级团队归纳，**不是史料**，不能当讲解证据用） |

### 六标签 `tags`（七个字段全部必有，值均为 `string[]`，允许为空）

| 字段 | 对应原表列 | 词表 | 空缺数 |
| --- | --- | --- | --- |
| `era_broad` | 年代（标准化） | 封闭九选一：`新石器/商周/春秋战国/秦汉/魏晋南北朝/隋唐/宋辽金元/明/清` | 1（`NMC-YQ-201` 二里头文化无法归档） |
| `era_specific` | 年代（具体） | 开放：`北朝`、`清`、`乾隆`、`红山文化` 等；一物可多值（`清 乾隆`→`["清","乾隆"]`） | 0 |
| `category_main` | 材质 | `瓷/玉/铜/青铜/陶/金/金饰/书画/纸本/纱/绸/织物/玛瑙/骨/石/鎏金铜`，多值 | 0 |
| `craft_types` | 制作工艺 | `青釉/刻花/刻纹/铸造/陶塑/三彩/黑釉/青花/釉里红/斗彩/五彩/粉彩/白釉/甜白釉/天青釉/模印/透雕/镂雕/高浮雕/浮雕/嵌螺钿/鎏金/缝制/织绣/金银平脱` 等 | 14（原表"待专家复核"） |
| `artifact_types` | 器类/用途 | `佩饰/带饰/首饰/罐/瓶/尊/盆/陈设或盛储器/壶/盛器/茶具/饮茶器/铜镜/镜相关图像/人物俑/服饰图像/玉礼器/仪仗器/服装/服饰实物` | 8 |
| `motifs` | 纹样/图像 | `龙/凤鸟/鸟/莲花/莲荷/花卉/葡萄/瑞兽/兽/人物/宴乐/舞人/铭文/文字/服饰形制` | 11（原表"无明显图像/待视觉核验"） |
| `themes` | 文化主题标签 | 封闭九选一：`工艺技术/茶生活/礼制身份/女性妆饰/中外交流/佛教图像/生活美学/亲子友好/纹样追踪` | 2 |

同维度内多值为 OR 关系；跨字段无顺序语义。原表里 `；`/`/`/`、` 分隔的多值、"X等Y"句式（`罐/瓶/尊/盆等陈设或盛储器`）已拆平为独立标签。

### 讲解史料 `materials[]`（对齐后端 GuideMaterial 契约）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `material_id` | str | 如 `NMC-CQ-104-m1`，一物目前仅 1 条 |
| `text` | str | **官方介绍摘录（A 级来源）**，是本地讲解史料依据；联网开启时可靠搜索结果可补充缺失事实与背景，已明确的本地事实优先 |
| `source_refs` | str[] | `[官网URL, "modal id=104"]` 两项 |
| `related_relic_ids` | str[] | 从 edges 双向反填的关联文物（仅收录两端都存在的边），供讲解追问/串讲用 |

## edges.json（知识关联，非空间边）

`edges[]`，45 条，**有向**（source→target，方向无严格语义，可按无向用）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `relation_id` | str | `REL-001`…`REL-045` |
| `source_relic_id` / `target_relic_id` | str | 端点文物 |
| `relation_type` | str | 45 种自由文本（工艺演进/纹样延续/同类对照/纹样跨媒介/功能组合…） |
| `scenario` | str | 用户问题/路线场景短语，如"宋代点茶与斗茶" |
| `evidence_summary` | str | 证据摘要（基于官网说明整理） |
| `source_refs` | str[] | 如 `["CQ专题页105","CQ专题页107"]` |
| `confidence` | str | 枚举：`高`(26) / `中高`(9) / `中`(10) |
| `demo_priority` | str | 枚举：`核心`(19) / `候选`(26) |
| `available_in_demo` | bool | 端点是否都在 60 件内；当前全部为 true |
| `review_status` | str | 人工复核状态 |

**注意：本文件不是空间步行图。** 展厅间步行时间、入口/出口、楼层通路均未采集（待实地踩点），写路线规划代码时不要从 edges 推导空间拓扑。

## map.json（虚拟测试空间图）

为便于当前功能联调，`map.json` 根据 `galleries.json` 中的四个展厅生成最小连通图：入口 → 北17 → 北18 → 北19 → 南14 → 出口，并补充反向边。`walk_time_min`、坐标和节点名称都是测试估值，不代表实际馆内路线；真实地图替换时保持 `nodes`、`edges` 的字段契约即可。默认后端通过 `backend/catalog_data.py` 的 `JsonMuseumDataSource` 读取该文件。

## 若要接入现有后端（backend/route_models.py 等）

- `tags.era_broad/era_specific/category_main/craft_types/themes` → `ExhibitTags` 同名字段，直接灌入；本次新增的 `artifact_types`、`motifs` 也由 `ExhibitTags` 保留，评分时分别参与器物/工艺和视觉特征匹配。
- `importance_level` → `Exhibit.importance_level`（1–5 整数，已合法）。
- `materials[]` → `GuideMaterial(material_id=…, text=…, source_refs=…, related_relic_ids=…)` 可直接构造，作为讲解选材适配器输出。
- 手记读取器 `JsonSummaryDataSource` 已直接消费本文件（只用 `relic_id/name/era/gallery_name`，其余字段忽略）。
- 空间快照 `MuseumSnapshot` 所需的 `SpatialEdge`（步行时间）来自独立的 `data/map.json`；当前为四个展厅 + 入口出口的虚拟最小连通图，待实地步行分钟数替换。
- 向量：relics 未存向量，需用与查询同一 embedding 模型对 `name + tags 拼接文本` 现算；空标签维度拼文本时跳过。

## 已知数据质量问题（写代码时要防）

1. `NMC-TJ-015`（候选档）无 `materials`——排到它时讲解选材要能报错/跳过。
2. `NMC-YQ-201` 的 `era_broad` 为空数组。
3. 六标签存在空缺（craft 14 / artifact 8 / motifs 11 / themes 2 件），评分逻辑必须容忍某维度为空（该维度不计入分母，不能当 0 分惩罚）。
4. 原表材质列有少量事实噪音（如长沙窑瓷壶被标 `铜/青铜`，Excel 标注待人工复核），已按原样转换，勿在代码里"纠正"。
5. `route_value` 是团队归纳（C 级），只能用于推荐理由展示，不能进讲解史料。
